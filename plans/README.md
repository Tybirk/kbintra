## Findings considered and rejected (do not re-audit)

- **WebSocket listener leak in `frontend/src/api/messaging.ts`**: false — `connect()` guards `setupEventListeners()` with `if (!this.visibilityHandler)`; listeners attach exactly once.
- **Food-ticket claim IDOR (`ClaimFoodTicketView`)**: authorization check exists post-fetch; residual is 403-vs-404 enumeration noise among authenticated residents. Not worth doing.
- **FTS search leaking members-only files**: visibility filter is applied post-query (`apps/search/views.py`); residual is existence-enumeration only. Not worth the index schema change.
- **Missing pagination on list endpoints**: at ~90 users, unbounded lists are fine; revisit only if data volume complains.
- **`useVersionCheck` stale `lastCheckRef`**: worst case is a ~30 s delay in update detection. Not worth doing.
- **Event capacity RSVP race**: speculative (capacity enforcement not verified to exist); investigate only if oversubscribed events are reported.
- **Playwright/E2E suite**: high value but L effort + flake maintenance conflicts with the stated low-maintenance goal; `MANUAL_TEST_GUIDE.md` remains the regression net. Reconsider if manual testing becomes the bottleneck.
- **Search-signal silent failures**: handlers log `OperationalError` and the startup `rebuild_search_index --if-empty` exists; a stale-index incident would justify a retry queue, not before.
- **Hardening bundle (validator edge-case tests, Fernet startup validation)**: presented as findings #8/#10 in the audit; the operator chose not to plan them this round. The booking-overlap edge cases (adjacent bookings, midnight ends, recurring exceptions) remain the most defensible future addition.
